## Observations

1. **Stale capture notice (#48 family).** On the shared tab after f1 succeeded, the popup still showed "Your agent's last action ran, but Chrome could not capture…" (`20`). The notice cleared only when the human paused and resumed. Opening a new consent afterwards showed no leftover notice this time (`28`).
2. **Agent wording shown to the human.** The popup's Recent activity lists the `screenshot_unavailable` message word for word ("…Ask the person to switch back…"). That text is written for the agent.
3. **Whether Chrome draws a background tab varies.** One of three background screenshots and two of three background clicks came back with a picture. That fits "either depicts the shared tab or returns `screenshot_unavailable`", but the skip-and-notice path appears only some of the time.
4. **#53: the skip path takes about 21 s.** The capture is bounded at 15 s. About 5 s more is spent after it on that path, likely the second privacy scan or the wait for navigation on a throttled background tab.

## Deviations

- **No human.** All "human" actions were synthetic X11 input (cua `click`/`type`/`key`). Popup and page states were judged from screenshots.
- **Extension loading.** Chrome for Testing was started with `--load-extension=/root/rt/dist/extension` and `--no-sandbox --disable-gpu`. Profile B was a second process, used only for the used-code check and then closed.
- **Harness error.** The first Act submit appended the code to the leftover `rt1.bad`, because the synthetic select-all did not clear the field. The session stayed `created`, not redeemed. The field was cleared with Backspace and the same code was typed again.
- **Private codes** were moved by script, from the downloaded create output into one `type` op, and the local copy was deleted at once. No code, token or credential appears in any output or screenshot.
- **Setup.** `NEEDRESTART_MODE=l` was set for apt, so `vnc-desktop.service` was not restarted and setup was not interrupted this time.
